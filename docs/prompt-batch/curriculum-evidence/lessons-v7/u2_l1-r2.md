Here's something that might surprise you: an AI trained on photos from the entire internet can still "think" the world looks mostly American — not because anyone programmed that in, but simply because of where the photos came from.

That's the core idea of today's first concept: **data bias**.

Before a model learns anything, someone has to collect the training data. Whatever gaps, skews, or historical patterns exist in that data get baked into the model before a single line of model code is written.

[EX]A geolocated sample of ImageNet — one of the most influential image datasets in AI history — found about 45% of images came from the US, while China and India contributed roughly 1% and 2% respectively (Shankar et al., 2017). A model trained on that data learns a skewed picture of what the world looks like.[/EX]

[KEY]Data bias means the model inherits whatever gaps and historical patterns existed in its training data — before any algorithmic choices are made.[/KEY]

Now for the second stage: **algorithmic bias**.

Even with perfect data, the choices engineers make — what to optimize for, how to measure success, which features to include — can introduce bias independently.

The optimization target is the sneaky part. You pick a number to maximize, and the model chases it. If that number is a flawed stand-in for what you actually care about, the model learns the flaw.

[EX]Imagine a school builds a tool to predict which students will "succeed" — but defines success as graduation rates, which historically skew toward students from wealthier zip codes. The model learns to favor those students, not because the data was bad, but because the target metric was a poor proxy for actual potential. (This scenario is made up, but the pattern is real.)[/EX]

[KEY]Algorithmic bias comes from the choices engineers make — what to optimize, what to measure, which features to include — independent of the data itself.[/KEY]

Now the third and final stage: **deployment bias**.

A model can be built on good data with careful design choices — and still produce biased outcomes because of *where and how it gets used*.

This happens when a tool is tested on one population but deployed on a different one, or used in a context it was never designed for.

[EX]Imagine a hiring tool trained and tested entirely on applicants from large tech companies in California — then deployed by a rural hospital to screen nursing candidates. The tool was never validated for that population or role. Any skews in who it favors get imported into a completely new context. (Made-up scenario, real pattern.)[/EX]

[KEY]Deployment bias occurs when a model is used on a population or in a context it wasn't designed or validated for — even if the data and algorithm were carefully built.[/KEY]
