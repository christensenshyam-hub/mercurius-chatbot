# Mercurius for Mac: a native SwiftUI app, a universal purchase with iOS

> **Stacked on #43** (`fix/ios-student-2026-10`, the latest iOS UI). This PR's base is that branch, so the diff shows only the Mac work. **After #43 merges, retarget this PR to `main`.**

## What this is

A native macOS app for Mercurius, built with SwiftUI. It isn't Catalyst, the iPad app running on a Mac, or Electron. Students can use it on their own Macs, beside a browser or a Google Doc.

- **Distribution:** the Mac App Store, as a **universal purchase** with the iPhone/iPad app. Release builds use the same bundle id, `com.mayoailiteracy.mercurius.native`, and it goes into the same App Store Connect record (Add Platform → macOS).
- **The same tutor:** the same production server and the same consent and age gate, lessons, unit checks, chat modes, reporting, delete-my-data, crisis support and reminders. Only the window around them is new.
- **Mac-shaped:**
  - a `NavigationSplitView` window: Today, the learning path by unit, and Chats;
  - a real toolbar and menu bar;
  - a native Settings window and a Help window;
  - keyboard-first: Return sends, Escape leaves, A–D answers a unit check;
  - a reading column with its own type sizes;
  - right-click to Copy or Report, and drag, drop or paste for homework photos.

## Architecture: what's shared with iOS

- **One more target, the same packages.**
  - `MercuriusMac` (in `ios/project.yml`) is a thin `@main` shell: a single `Window`, the `Settings` scene, a Help window, the menu commands and the DEBUG screenshot harness. Like the iOS app's project, it's generated by xcodegen; nothing is hand-edited.
  - Everything else is the local Swift packages, which already built for macOS because `swift test` runs on the Mac host.
- **The Mac window is composed in AppFeature**, in `AppFeature/Sources/Mac/`, all `#if os(macOS)`:
  - `MacShellView`, `MacShellModel`, `MacSidebar`, `MacTodayView`, `MacCommands`, `MacSettingsView`, `MacHelpView`.
  - AppFeature stays the only composition root, so the dependency graph `ArchitectureTests` pins is unchanged. `swift test` compiles and tests the Mac code on every run.
- **The gate logic is shared, not copied.** `RootView` → `AppEntryView` (the gate decision, the reminder re-plan, consent withdrawal) runs on both platforms. On the Mac it mounts `MacShellView` and hands it the same `OnboardingFlow` while the gate shows.
- **The detail column hosts the iPhone's views:** `ChatView`, `CurriculumLessonView`, `UnitTestView`, `CurriculumView`, `OnboardingFlow` and `CrisisSupportView`. The Mac's differences live in them behind `#if os(macOS)`, or as DesignSystem modifiers that return the view unchanged on iOS (`macReadableColumn`, `macHoverHighlight`, `macPointingHand`, `macDefaultAction`).
- **The Settings window** is `MacSettingsWindowView` (SettingsFeature) on the iPhone's own `SettingsViewModel` and reset wiring.
- **Type sizes:** macOS gives SwiftUI apps no Dynamic Type, and its text styles are sized for dense UI (body 13 pt, footnote 10 pt). So the Mac has one explicit ramp, `MacTypeRamp`: body 15, captions at least 12, and Merc's replies at the same 15 pt in Lexend. `BrandFont` reads it under `#if os(macOS)`; iOS keeps its text styles.
- **Bundle ids:**
  - Release is `com.mayoailiteracy.mercurius.native`.
  - Debug is `….native.macdev`, so a development run never shares the data folder of the iPad app installed on the same Mac.
- **The server is unchanged.** The Mac talks to production exactly as the iPhone does, and today the server can't tell them apart. We recommend an additive `X-Mercurius-Client: macos/<version> (<build>)` header (and `ios/…`), read by a later server change. Not a body field: several routes validate with `.strict()` schemas. It's not in this PR.

## Mac-specific behaviour

- **Window:**
  - The sidebar has Today, Learning path (one row per unit, foldable) and Chats.
  - Chats has a New Chat row, which stands for an unsaved new thread, then the saved threads. The Delete key or a right-click deletes one, after a confirmation.
  - The window is 700 pt wide at minimum, so it tiles beside a browser on a 13" MacBook. Below 860 pt the sidebar folds itself away, and it comes back when the window widens.
- **Today** is an overview:
  - Merc's greeting;
  - Up next (the unit, lesson, goal and unit progress; Return starts it);
  - This week;
  - Streak (never a "0");
  - Recent chats;
  - the weekly-nudge offer.
- **Toolbar:**
  - Lessons and unit checks put their title, a subtitle (Unit 1 · Lesson 1 of 4) and the way back in the toolbar.
  - The chat has the Socratic / Debate / Discussion picker, Explain More and New Chat.
  - The streak is a toolbar button that opens Progress.
- **Menu bar:**
  - File: New Chat ⌘N, Attach Image… ⇧⌘A.
  - Chat: the modes ⌥⌘1–⌥⌘3 (only while the chat is in front), Retry ⌘R, Explain More ⇧⌘E.
  - View: Today, Learning Path, Chat (⌘1–⌘3), and the sidebar commands.
  - Help: Mercurius Help ⌘?, plus support links.
  - Settings is ⌘,.
- **Keyboard:**
  - In the composer, Return sends, Shift-Return adds a line, and Option-Return and input methods behave as usual.
  - Return presses each first-run step's button.
  - Escape leaves a lesson, a unit check or the support screen, but only when nothing would be lost.
  - In a unit check, A–D or 1–4 answer the highlighted question, Tab, ↑ and ↓ move between questions, and ⌘Return submits.
- **Pointer:**
  - Cards tint on hover.
  - The pointing hand appears on links only.
  - Icon-only controls have tooltips.
  - Right-click a reply to Copy it or Report it.
- **Images:** the composer's image button (an open panel), drag and drop, or paste.
- **Reminders:** UserNotifications, as on iOS. Clicking one opens its lesson.
- **Not on the Mac:** the Live Activity, widgets and haptics (iOS-only), and the App Store review prompt (not wired yet).

## Safety and consent parity

- **No network call before consent.**
  - While the gate shows, the detail column *is* the gate, and the sidebar is hidden and disabled.
  - Every menu command is off, the Settings window is a placeholder, and the shell's server tasks wait.
  - Shown by code reading and by fresh-container launches against a logging server: 0 requests on the gate, versus 2 in a control run past it (`VERIFY.md` §5).
- **Age gate.** The same under-13 stop. The test-hook launch arguments (`-UITests`, `-KeepAgeBlock`, `-SeedDemoChat`) are now DEBUG-only, because a Mac App Store build can be launched with arguments.
- **Crisis support.** On a Mac, `tel:`/`sms:` open FaceTime or Messages, which may not be set up and may do nothing. So the numbers (988, HOME to 741741, 911) are large, selectable text with Copy buttons, in one card. The FaceTime/Messages links follow, with an honest note at body size. It's reachable from a unit check, a quiz, and Help ▸ Get Help.
- **Delete my data / reset / withdraw consent** use the iPhone's `SettingsViewModel`, in the Settings window.
  - The main window holds still while an erase runs.
  - A lesson open in the main window has its reply stopped *before* the server delete, then closes, so nothing of the erased session is replayed under the new ID.
  - The menu's shell commands are off meanwhile.
- **Report a reply:** right-click ▸ Report response ▸ a reason, using the same path and feedback alert as iOS.

## Release tooling (`ios/scripts/`)

- **`provision.sh --platform mac`** is additive:
  - it reuses the Apple Distribution certificate;
  - it adds a Mac Installer Distribution certificate and the "Mercurius Mac App Store" profile;
  - it never revokes anything.
  `--check` is read-only.
- **`release.sh --platform mac`** archives `MercuriusMac` (universal), exports a `.pkg` with `ExportOptionsMac.plist`, uploads with `altool --type macos` and tags `mac/v<version>-<build>`. A preflight checks the Mac profile and both identities.
- **`asc-api.sh`** is the shared App Store Connect plumbing. It stops with a plain message on the 403 "required agreement missing" that blocks the account today.
- **`mac-bundle-check.sh`** checks a built bundle, as described under CI.
- **`mac-snapshots.sh`** and **`mac-store-screenshots.sh`** are the harness's set, and the Mac App Store's 2560 × 1600 opaque PNGs.
- The iOS path of every script is unchanged; an iOS dry run archived and exported as before.

## What the founder does (`docs/mac-app/FOUNDER_STEPS.md`)

1. **Accept the pending Apple agreement** (Account Holder) at developer.apple.com/account and App Store Connect → Business. Until then, every App Store Connect API call answers 403.
2. **Check the App ID** `com.mayoailiteracy.mercurius.native` is usable on macOS (`provision.sh --check --platform mac` prints its platform).
3. **Provision:** `cd ios && ./scripts/provision.sh --platform mac`.
4. **Add macOS to the Mercurius AI record** (Add Platform → macOS, version 2.3.0). The same bundle id makes it the universal purchase; there's no separate switch. Name, age rating, privacy label, price and territories are shared with iOS.
5. **Uncheck "iPhone and iPad Apps on Apple Silicon Macs"** under Pricing and Availability, so Macs get the native app, not the iPad one.
6. **Upload to TestFlight:** `./scripts/release.sh --platform mac`. Rehearse in TestFlight for Mac:
   - the gate, a lesson, a chat;
   - Report;
   - Delete My Data;
   - the crisis numbers;
   - a reminder.
   Also see what happens to the iPad app's local data on your Mac when the native app replaces it.
7. **Screenshots:** `scripts/mac-store-screenshots.sh <dir>` on an **unlocked** Mac, with nobody typing for about a minute. Each shot activates the app and the script refuses inactive or blank pictures. Look at each one before uploading (`docs/APP_STORE_LISTING.md` §7.2).
8. **The macOS version page:** paste the description, keywords and **App Review notes** from `docs/APP_STORE_LISTING.md` §7. The notes cover the gate, the modes, reporting, deletion, crisis support, the under-13 stop surviving an app deletion on a Mac, and separate sessions per device.
9. **Submit**, releasing manually as for iOS.

## Known gaps

- **No cross-device sync.** There are no accounts. A student's Mac and iPhone are **separate anonymous sessions**, each with its own progress, streak and chats. The Mac description and the review notes say so. Closing this gap needs accounts or a pairing scheme, which is a product decision.
- **The session id stays on the Mac, but not like iOS.** It's in the login keychain: it never syncs through iCloud, but it moves to a new Mac with Migration Assistant. Moving it to the data-protection keychain is tied to the iPad-on-Mac question and needs a TestFlight build.
- **No Live Activity, widgets or haptics** on the Mac (iOS-only), and no App Store review prompt yet.
- No Mac UI-test target, no window-state restoration, and no text-size control (the Mac's body is a fixed 15 pt).
- The committed screenshots show an inactive window (see above).
