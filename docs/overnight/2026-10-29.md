## Round 2: four more PRs, each stacked on its round-1 PR

Merge the round-1 PR first. GitHub then points the round-2 PR at main by itself.

**CI doesn't run on a stacked PR by itself**, because the workflows only trigger on PRs into main. I started the Server and iOS workflows by hand on each round-2 branch. Their results are in the Actions tab under "workflow_dispatch".

### [#75](https://github.com/christensenshyam-hub/mercurius-chatbot/pull/75) Server: limits that survive a deploy (stacked on #67)

- **A deploy no longer gives a school network a fresh day.** Its dollar and photo allowances were kept only in memory. They are now read back from the usage ledger after a restart, the same way a session's turns already were. The ledger still stores only the salted hash of the address.
- **Photos uploaded at the same moment can't get past the daily photo limits.** Before, 6 uploads fired together were all stored against a cap of 2. Now an upload is counted when it is let in and handed back if the save fails.
- **When the student leaves, the answer guard's rewrite stops.** Before, it ran to the end and was billed in full. Now it is cancelled and recorded as "aborted". It doesn't count as an error, so it can't set off the Discord alert.
- Tests: 1975 of 1975 pass. The new Postgres SQL passed on real Postgres in a CI run I started by hand.
- Limits:
  - The first deploy resets that day's photo counts one last time, because earlier uploads have no ledger rows.
  - A network's new-session and report counts still reset on deploy.
  - The cost of a cancelled rewrite is an estimate.

### [#72](https://github.com/christensenshyam-hub/mercurius-chatbot/pull/72) iPhone: Merc's greeting matches the button (stacked on #68)

- Before, if the progress pull landed after Home was showing, the button said "Continue · Lesson 3" while Merc still said "Your first lesson is ready".
- Now the bubble follows. If the line was already said, it crossfades to the new one. If it was still being typed, it types on into the new line.
- Checked on the simulator for both cases. 1582 Swift tests pass.
- The agent looked hard for a second iPhone bug in areas round 1 didn't cover (certificates, delete-my-data, reminders, the largest text sizes, VoiceOver on Basics) and found nothing it could show was broken.

### [#74](https://github.com/christensenshyam-hub/mercurius-chatbot/pull/74) Lessons: a wrong answer no longer costs Unit 1 Lesson 1 two of its ideas (stacked on #69)

- Before, after a wrong tap, the tutor reached the exercise without teaching embeddings and attention in 3 of 4 trials. With the fix, all three ideas were taught in 8 of 8 trials (the fixer's 5 and the reviewer's 3).
- The reviewer also fixed two measuring tools the change had broken. One is the merge gate's blocks lesson, which now taps one more check before it sends its exercise answers.
- **Needs a teacher:** with attention now taught, the tutor often says "bank" looks at "river" in "I sat on the bank of the river". In a GPT-style model a word only looks back at earlier words, so "bank" can't see "river". Round 3 is looking at this.
- Still the case: after a reteach, the tutor often calls the next idea "one more piece" or "the last step".
- The full $11 eval gate is still required. The gate's "preview" row may trip on harmless "First, ... Second," wording.
- Cost: $1.10.
