# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Mercurius — an AI-literacy tutor for high-school students (Claude-backed, Socratic-first). One Node/Express server serves three clients: an embeddable vanilla-JS web widget, a native SwiftUI iOS app (`ios/`, the primary surface — shipped on the App Store), and the static marketing site. The club site (mayoailiteracy.com) lives in the separate `mayo-ai-literacy-club` repo (`mayo-site/` there). `mobile/` is a legacy Expo prototype — do not touch it.

## Commands

### Server (repo root)
Standard npm scripts (see `package.json`). `npm run dev` needs a `.env` with `ANTHROPIC_API_KEY`.

### iOS — SPM packages (fast loop, runs on macOS host)
Standard SPM commands from `ios/Packages`. `swift test` includes the architecture rules.

### iOS — app build/tests (simulator)
```bash
cd ios
xcodegen generate                    # ALWAYS regenerate before xcodebuild — see below
xcodebuild build -project Mercurius.xcodeproj -scheme Mercurius \
  -destination 'platform=iOS Simulator,name=iPhone 16' -derivedDataPath build/dd
xcodebuild test -project Mercurius.xcodeproj -scheme Mercurius \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  -only-testing:MercuriusUITests/MercuriusUITests/testBootCompletes   # single UI test
```

### Mac app (`ios/MercuriusMac`, scheme `MercuriusMac`)
A native SwiftUI Mac app (not Catalyst), a universal purchase with iOS: same bundle id in Release, `….macdev` in Debug so dev runs never share the installed iPad-on-Mac app's sandbox container. Its window lives in `AppFeature/Sources/Mac` (`#if os(macOS)`, so `swift test` compiles and tests it): `AppEntryView` mounts `MacShellView` (a `NavigationSplitView`) and hands it the consent gate while it shows. Mac-only behaviour in the shared views (Return/Shift-Return composer, image drop/paste/open panel, reading columns, hover, right-click Copy/Report, the chat toolbar, `ChatCommandTarget` for the menu's Retry/Explain More/Attach) is `#if os(macOS)`; DesignSystem's `macReadableColumn` / `macHoverHighlight` / `macPointingHand` return the view unchanged on iOS — keep iOS identical. The Settings window is `MacSettingsWindowView` (SettingsFeature) on the iPhone's `SettingsViewModel`; Help is `MacHelpView`. Reminders run on the Mac too; `NotificationScheduler.center` is nil outside an app bundle because `UNUserNotificationCenter.current()` traps in the `swift test` host. macOS gives SwiftUI apps no Dynamic Type (`.dynamicTypeSize` and `@ScaledMetric` don't scale there), so the Mac's text sizes are one explicit ramp, `MacTypeRamp` (body 15, captions ≥ 12, replies the same 15 in Lexend), read by `BrandFont` under `#if os(macOS)` — size Mac text through `BrandFont`, not text styles (`.footnote` is 10 pt on a Mac). On the Mac the window's toolbar carries a lesson's or unit check's title, subtitle and way back (no in-content header rows), ⌘1–⌘3 are Today / Learning Path / Chat and ⌥⌘1–⌥⌘3 the chat modes (only while the free chat shows), and the main scene is a single `Window`. Screenshots: `ios/scripts/mac-snapshots.sh <dir> [state…]` — the DEBUG `-MacSnapshot <dir>` harness photographs the app's own window (Liquid Glass surfaces come out dark or blank; see `MacSnapshot.swift`), light/dark at 1280×800 and the 700×600 minimum; it activates the app and fails a picture that's the wrong size, one colour (a locked or sleeping screen) or of an inactive window (`ACTIVATE=NO` accepts inactive); `-MacSnapshotWindow settings|help` + `-MacOpenWindow` for the other windows; `-MacSnapshotType <text>` (`|` = Shift-Return) and `-MacSnapshotSubmit YES` type into the composer with real key events. Give every launch flag a value (`-EnterShell YES`): a bare word after a flag is opened as a document and SwiftUI then shows no window. Plan and step notes: `docs/mac-app/`.

### iOS — release tooling (`ios/scripts/`)
- `provision.sh` — bootstraps the Apple Distribution cert + BOTH App Store profiles (app + `MercuriusWidgets` appex) via the ASC API. Credentials in `~/.appstoreconnect/`; dedicated keychain `mercurius-codesign.keychain-db`. `--platform mac`: additive — reuses that cert, adds a Mac Installer Distribution cert and the `Mercurius Mac App Store` (MAC_APP_STORE) profile, never revokes. `--check` is read-only.
- `release.sh` — bump build number → xcodegen → archive → export → altool upload. `--no-bump` / `--no-upload` flags. `--platform mac`: `MercuriusMac`, `ExportOptionsMac.plist` → `.pkg`, `altool --type macos`, tag `mac/v…`; a preflight checks the Mac profile/identities (exit 13) and asks ASC first.
- `asc-api.sh` (sourced by both): JWT + API calls. An unaccepted agreement (HTTP 403 `FORBIDDEN.REQUIRED_AGREEMENTS_MISSING_OR_EXPIRED`) stops with an explanation, exit 21; also detected in xcodebuild/altool output (`build/release-logs/`).
- `mac-bundle-check.sh <app> debug|release` (CI's Mac job runs it), `mac-store-screenshots.sh <dir>` (2560×1600: the 14" MacBook Pro's 888-pt visible height can't hold the 900-pt window 2880×1800 needs; the screen must be unlocked or captures come out blank).
- `screenshots.sh` — App Store screenshots via the `AppStoreScreenshots` UI test on iPhone 6.5" + iPad 13" sims.

CI (`.github/workflows/`): `server.yml` runs `npm test` on Node 20/22; `ios.yml` runs `swift test` on macOS plus `xcodebuild test` on a simulator, and a `mac` job (unsigned Debug + universal Release builds of `MercuriusMac`, `mac-bundle-check.sh`, a launch smoke test through `mac-snapshots.sh`). CI regenerates the Xcode project with xcodegen — anything not in `project.yml` does not exist on CI.

## Critical: the Xcode project is generated

`ios/Mercurius.xcodeproj` is **gitignored** and produced by `xcodegen generate` from `ios/project.yml`. The app target's Info.plist is also written by xcodegen from the `info.properties` block. Never hand-edit the pbxproj or the app Info.plist — the next generate silently reverts it. New targets need the repo's xattr-strip `postBuildScripts` phase (see below).

## Architecture

### Server (`server.js` + `db.js` + `lib/`)
A single Express app. `server.js` holds the routes and the Claude streaming logic (SSE); `db.js` is a guarded better-sqlite3/Postgres layer; `lib/` holds extracted pure modules (prompt assembly in `unifiedPrompt.js`, gamification, image validation/store, unit-test grader, rate limiter). System prompts live in `prompts/mercurius-v2.md` and per-mode instructions in `lib/unifiedPrompt.js`.

**Every model call goes through `lib/claudeCall.js`** (`createMessage` / `streamMessage`) — never the SDK directly. It is the one place that settles usage exactly once per call (including aborted streams), prices it (`lib/pricing.js`), feeds the dollar budget (`lib/spendCap.js`, `DAILY_BUDGET_USD`), the per-session/per-IP daily quotas (`lib/quotas.js`), Prometheus, the `usage` ledger, and Discord alerts (`lib/alerts.js`). Every model route runs `gate(req, res, { kind })` first (draining → kill switch → budget → quotas → in-flight caps). `ANTHROPIC_MOCK=1` swaps in `lib/anthropicMock.js` so the server can be integration-tested with no key (refused when `NODE_ENV=production`). There is no per-student memory profile any more — do not reintroduce one.

**Trust + ops rails.** Content reports (`POST /api/report`, reason + preceding user turn + context; `REPORT_IP_PER_MIN` per IP, 60 by default; silently dropped for a session the server has never seen) land in an admin review queue (`GET /api/admin/reports`, `POST /api/admin/reports/:id/resolve`) and page Discord via `lib/reportWebhook.js` with metadata only — never student or model text — under one throttled key. Lesson lifecycle rows (`lesson_events`: one row per answered turn, the opener being `start`; `complete` once per attempt) are written from the chat handler after the reply; `GET /api/admin/stats?days=7` is the founder's weekly numbers (DAU/WAU, lessons, cost, D1/D7) plus live rails state. `lib/scheduler.js` runs in-process (one replica, no cron): a daily Discord digest (one `getAdminStats({ days: 7 })` through `digestStatsFromAdminStats`, headlining the last complete UTC day) and the retention sweep (`*_RETENTION_*` env; reports are kept 180 days, open or resolved; `curriculum_progress` is never purged). Off under `NODE_ENV=test`.

**Prompt assembly is cache-shaped.** Every model call sends one byte-stable static system block (`cache_control: ephemeral`, composed once via `lib/systemBlocks.js`: mode prompt + club knowledge for `club_v1` clients only + source library + the shared `lib/safetyCore.js` block LAST) plus a small dynamic block (runtime context, widget meeting/blog material, the "explain more" nudge). Anything per-request goes in the dynamic block — one byte of drift in a static prefix is a full cache miss. The conversation is the client's own thread (lesson threads normalized by `lib/curriculumTag.js`), never a replay of the session's database history. Prompt changes must pass `scripts/eval-pacing.mjs --runs 3` in BOTH `USE_UNIFIED_PROMPT` states (start the eval server with `EVAL_EXPOSE_USAGE=1 IP_DAILY_NEW_SESSIONS=1000`).

**Homework coaching backstops** (`lib/homeworkGuard.js`, socratic homework review 2026-10-22). On a free-chat turn the server works out what it can exactly from the thread, every turn and with no stored state: a short note in the dynamic block (the verdict on the student's latest line of a linear equation, atom counts for a reaction, "check their formula answer with their own number", the next move when they keep asking, the writing opener); adaptive thinking at low effort for turns on a problem to work; and an answer guard that holds a reply back and regenerates it once (then redacts) when it states their answer, works a word problem's numbers through, or writes a correction they still have to find. The Quiz-me chip drops questions on the student's own equation. Rules live in `STUDENT_WORK_RULES`; these are the deterministic part.

**Server↔client contract markers** — the server embeds control tags in the streamed reply which every client must strip and act on: `[LESSON_COMPLETE]` (server judged proficiency; iOS flips lesson state, widget advances) and per-turn `[CURRICULUM]` tagging. If you touch these, update **all three**: `server.js`, iOS `ChatViewModel`/`NetworkingKit`, and the web widget(s).

**Progress sync** — `GET`/`PUT /api/progress/:sessionId` mirror the iOS `CurriculumProgressStore` in `curriculum_progress` (lesson `uN_lM` → `completed`, unit `unit_N` → `mastered`; in-progress lessons stay on-device) and merge **forward-only** (`PROGRESS_STATUS_RANK` in `lib/schemas.js`: `completed < mastered`, never a downgrade or delete), with the chat handler's own `[LESSON_COMPLETE]` judgement written server-side as belt and braces.

**Club facts (`club_v1` only)**: `lib/clubKnowledge.js` restates what the live club site (mayoailiteracy.com) says — name, board titles, the June 2026 AACA *poster* "Teaching the Pause" (never a talk), chapters, the Mayo Clinic non-affiliation, topics, resources — and nothing it doesn't (no member or meeting counts). It is a constant in the cached prefix: keep it byte-stable. The schedule, upcoming/past meetings and blog posts are NOT hard-coded: they come from the site's `events-data.json` / `blog-content.json` feeds (or the admin events row) via `lib/clubContext.js` into the dynamic block. When the club site changes, update `lib/clubKnowledge.js` to match it.

**One web widget**: `public/widget.js` + `public/widget.css` are the single source and the only copy (the club site dropped the widget in June 2026, and this repo's stale `mayo-site/` copy is gone). CI runs `node scripts/sync-widget.mjs --check`, which fails on a stale listed copy or any unlisted `widget.{js,css}` in the repo. Per-site settings go in each page's `window.MercuriusConfig`, not in the widget files. The widget's pure helpers (`Core`: escaping, markdown, SSE parsing, the first-run gate, history capping) are exported under Node and unit-tested there.

### iOS (`ios/Packages` — local SPM packages, thin app shell)
Almost all code lives in local packages; the app target (`ios/Mercurius/`) is a shell. Layering is **enforced by a test** (`ArchitectureTests/Tests/DependencyGraphTests.swift`):

- **Infra**: `DesignSystem` (tokens + the procedural Merc mascot: `Merc`/`MercState`/`MercMascot`), `NetworkingKit` (APIClient, SSE streaming, progress sync, SessionIdentity/Keychain), `PersistenceKit` (SwiftData chat store, UserDefaults stores: streak, reminders, last activity, review-prompt counter).
- **Features**: `ChatFeature`, `CurriculumFeature`, `SettingsFeature` — may depend on infra, NOT on each other (one reviewed exception: Curriculum → Settings). `EngagementFeature` (streaks/achievements/reminders UI, notification art, `NotificationRouter`) is likewise composed only at the root.
- **Composition root**: `AppFeature` (`AppShellView` wires everything — e.g. it injects `GamifiedTopBar` into the curriculum path's `topBar` slot and `StreakChip` into the chat header, because the features can't import EngagementFeature themselves). `AppEnvironment` owns the app-wide stores, including the one `CurriculumProgressStore`.
- **`LessonInteractives`**: the lesson interactives (the slate's cards): registry keyed by lesson id (`InteractiveRegistry`), predict-then-reveal, shared blocks and views with iPhone/Mac styling hooks. A content module: it may depend on DesignSystem ONLY (ArchitectureTests; NoIOTests scans its sources), so no card can send or store anything. Where a card sits in a thread is ChatFeature's (`Lesson/LessonInteractive.swift`); Lesson 1.1's tokenizer views stay in ChatFeature. New cards ship `enabled: false` until their teacher review. How to add one: `docs/interactives/FRAMEWORK.md`.
- **`MercuriusActivity`**: the Live Activity (attributes, Aurora theme, lock card, Dynamic Island) — shared by the app AND the `MercuriusWidgets` appex so both use the same types. All ActivityKit code is `#if os(iOS)` (NOT `canImport` — the types import on macOS but are unavailable, and the SPM test host compiles on macOS).
- **App target**: `MercuriusApp.swift` only builds `AppEnvironment` and installs `NotificationRouter.shared` as the notification-center delegate in its `@UIApplicationDelegateAdaptor` (it must be set before launch finishes, or a cold-launch reminder tap is lost). A tap on a reminder opens `mercurius://lesson/<id>`.

Identity is an anonymous session id in the Keychain (survives reinstalls); there are no user accounts.

**Gamification is double-gated**: `NetworkingKit/GamificationFlag.clientEnabled` (compile-time) AND a server flag. UI must degrade gracefully when disabled — never render zeros.

**DEBUG launch arguments** (see `RootView`/`AppEntryView`): `-EnterShell` / `-EnterShellCurriculum` skip the Home doorman; `-LiveActivityPreview` starts a demo Live Activity; `-LiveActivityGallery` (+`-LiveActivityGalleryBottom`) renders every activity phase in-app; `-NotifPreview` fires demo notification banners; `-ChatPreview`, `-LessonPreview` (+`-LessonSkipIntro`), `-MercPreview`; `-Interactive <slug>` opens a lesson interactive's lesson with its replay (stub replies, which say so, outside Unit 1 Lesson 1) and shows the card even while it ships dark, `-InteractiveGallery <slug>` shows a card alone (more in `docs/interactives/FRAMEWORK.md` §5); `-ForceCelebrate` shows the lesson-complete overlay (and its share card) inside a lesson without a real completion, so it never counts toward progress or the review prompt. First-run gate (2.3.0): `-consentVersion N` sets the consent flag through the UserDefaults argument domain (`0` shows the gate, `1` = `ConsentGate.currentVersion` bypasses it — the UI tests pass `1` by default; pair with `-hasSeenOnboarding NO` for the full first-run flow); `-ResetConsent` clears the persisted consent (and the under-13 block) so the gate shows again; `-GateStep <step>` opens the flow directly at one screen (`meet`, `age`, `underThirteen`, `disclosure`, `paused`, `limits`, `path`). An under-13 answer is remembered on the device for `AgeBlock.coolOffDays` (a timestamp under `ageBlockedAt`, never the age), and while it holds the gate opens on the block screen. Use these for screenshot verification — there is no CLI way to tap through the UI. `-UITests`, `-KeepAgeBlock` and `-SeedDemoChat` are read only in DEBUG builds (`AppEnvironment.testHookArguments`: a Mac App Store build can be launched with arguments). `-UITests` (passed by every XCUITest) gives lesson progress, last activity, the Home reminder card and the age block private UserDefaults suites that are wiped at each launch, so each test starts on Home at Lesson 1 (`-KeepAgeBlock` keeps the age block across a relaunch); `-SeedDemoChat` loads a 50-message chat for App Store screenshots.

### Marketing site (`marketing/`, trymercurius.com)
Static HTML/CSS/JS that Netlify deploys from `main` with `marketing/` as the publish folder, so **every file in it is public** (and Netlify finds a file whatever the case of the URL, so a `_redirects` rule can't hide one). Keep docs, notes and data out of it: the site's developer docs are `docs/marketing-site.md` (structure, generators, checks, local preview), the design system is `docs/marketing-design.md`, and `tests/marketingNotFound.test.js` fails on any file there that isn't part of the site. The shared head/header/footer, the reel cards and the lesson replay are generated by `scripts/build-site-chrome.mjs`, `build-reels.mjs` and `build-demo-replay.mjs` (each has `--check`); bump `CSS_V`/`JS_V` in `build-site-chrome.mjs` when `styles.css`/`script.js` change.

## Known build traps (all recur)

- **iCloud " 2" duplicate files**: the repo lives on an iCloud-synced Desktop, which spawns byte-identical `Foo 2.swift` copies. Any inside a package `Sources/` breaks clean builds with redeclaration errors. Delete them on sight (they're always untracked; verify with `git status`).
- **Codesign xattr failures** ("resource fork, Finder information, or similar detritus not allowed"): every target carries a "Strip extended attributes" script phase in `project.yml`, but the race still intermittently fails builds. Remedy: retry the build (loop `for i in 1 2 3`); if persistent, `rm -rf` the built .app and rebuild.
- **Stale module cache**: "cannot find type X in scope" for types that clearly exist means a corrupted/stale DerivedData module cache. `rm -rf` the derived data in use (`ios/build/dd` or `~/Library/Developer/Xcode/DerivedData/Mercurius-*`).
- **xcodebuild hangs at invocation** (no output for minutes): CoreSimulator is wedged. `pkill -9 xcodebuild XCBBuildService`, `launchctl remove com.apple.CoreSimulator.CoreSimulatorService`, reboot the sim, retry.
- **Snapshot reference recording is user-owned**: never launch snapshot record runs; defer (re)recording to the user and verify UI via simulator screenshots instead.

## Verifying UI changes

Build → `xcrun simctl install/launch` with a DEBUG launch arg → `xcrun simctl io <udid> screenshot` → inspect the PNG (crop/zoom/pixel-measure with Python + PIL for precise claims). Live Activities survive app termination, so terminate the app to photograph the Dynamic Island. UI tests anchor on the Home "Chat with Merc" button, the "Debate" mode pill, the "Settings"/"Home" header buttons, the Chat/History/Curriculum tab labels, the lesson intro's "Continue. Start the lesson." button, and the `onboarding.*` / `settings.*` accessibility identifiers — keep those if the UI around them changes.
